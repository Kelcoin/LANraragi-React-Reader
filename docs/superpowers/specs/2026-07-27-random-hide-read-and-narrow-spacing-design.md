# 窄屏间距与随机漫游隐藏已读完设计

## 目标

1. 缩小窄屏下“全部档案”面板左右留白。
2. 新增独立的“随机漫游中隐藏已读完”开关。
3. 首页随机漫游和阅读页快速跳转中的随机漫游使用相同过滤规则。
4. 配置导入导出包含新开关。
5. 项目版本从 `1.4.5` 提升到 `1.4.6`。

## 布局

仅将 Home 页“全部档案”面板的窄屏横向内边距从 `14px` 调整为 `8px`。页面根容器和其他面板不变，避免影响导航、轮播及设置面板的既有对齐。

## 设置与持久化

新增本地配置键 `lrr_random_hide_read`：

- 默认关闭，保持升级前行为。
- 设置面板中紧跟在“历史记录中隐藏已读完”之后。
- 标签为“随机漫游中隐藏已读完”。
- 只控制随机漫游，不与历史记录隐藏开关联动。
- 加入 `CONFIG_KEYS`，因此现有配置导入导出流程自动携带该字符串配置值。

该设置不需要 Worker 同步；配置导出仍可用于设备迁移。

## 过滤规则与数据流

新增小型纯函数，统一完成以下处理：

1. 使用 `arcid` 或 `id` 匹配随机档案与阅读历史。
2. 当前页取随机档案自身的 `progress/page` 与历史记录 `page` 中的有效最大值。
3. 总页数取档案或历史记录中的 `pagecount/total`。
4. 当总页数大于零且当前页大于等于总页数时，判定为已读完。
5. 开关关闭时原样返回；开启时排除已读完档案。

首页 `fetchRandoms` 在批次评分和写入状态前应用过滤，防止已读档案影响新鲜度评分，并让现有自动补齐逻辑继续请求候选档案。快速跳转在 `getRandom(16)` 返回后用同一函数过滤，再写入 `randomEntries`。

## 错误与空结果

- API 请求失败沿用现有错误处理。
- 开启过滤后没有候选档案时，沿用“暂无随机漫游结果”。
- 无总页数或无进度的档案不视为已读完，避免误隐藏。
- 导入旧配置时新键缺失，按默认关闭处理。

## 测试与验证

- 纯函数测试：关闭开关、档案自身进度、本地历史进度、缺失总页数、混合 ID 字段。
- 配置测试：新键导出、导入与旧配置兼容。
- 回归契约：设置控件、Home 与 Reader 均调用共享过滤逻辑。
- 布局测试：窄屏“全部档案”横向内边距为 `8px`。
- 更新 package 与 lockfile 的版本断言。
- 运行完整 test、lint、build、audit 及 `git diff --check`。
- 在 711×1138 视口检查面板间距和设置控件的深浅主题显示。

## 非目标

- 不改变历史记录隐藏设置的 Worker 同步方式。
- 不修改 LANraragi 随机 API。
- 不增加随机请求次数上限或新的重试策略。
- 不调整其他 Home 面板的窄屏间距。
